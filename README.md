# Поиск объявлений на OLX Узбекистан

Личный Telegram-бот с независимыми темами поиска и текстовыми уведомлениями
Темы создаёт владелец в личном чате с ботом

## Сначала проверь доступ с хостинга

Если бот отвечает в Telegram, а объявления не приходят, проверь OLX из того же контейнера, где запускаешь бота

1) Распакуй ZIP в рабочую папку сервера и выбери Python 3.11 или новее
2) Укажи main.py как стартовый файл и установи зависимости из requirements.txt
3) Скопируй .env.example в .env и поставь DIAGNOSE_ONLY=1 или задай эту переменную в панели
4) Запусти сервер и прочитай вывод в консоли, для этой проверки токен не нужен
5) Верни DIAGNOSE_ONLY=0 перед запуском мониторинга

Если доступен терминал, можно проверить отдельно

```sh
python -m pip install -r requirements.txt
python diagnose.py велосипед
```

Скрипт сначала проверяет выдачу, затем пробует получить телефон первого объявления
Пустая выдача означает, что ответ получен, но проверить телефон на этом запросе не получилось

| Результат | Что произошло |
| --- | --- |
| HTTP 403 | OLX отклонил запрос, уточни у OLX или хостинга, разрешён ли доступ с этого IP |
| HTTP 429 | OLX просит снизить частоту, увеличь REQUEST_GAP и CHECK_INTERVAL |
| TimeoutError | Ответ не пришёл за 15 секунд, это само по себе не доказывает блокировку |
| ClientConnectorError | Не удалось установить соединение, проверь DNS и исходящий HTTPS у хостинга |
| Ошибка формата | Ответ отличается от ожидаемого, нужно проверить актуальные поля OLX |
| Выдача доступна, ошибка на телефоне | Поиск работает отдельно от телефонов, поставь FETCH_PHONE=0 для мониторинга без них |

## Запуск бота

В .env или в переменных панели укажи BOT_TOKEN от BotFather и OWNER_ID, числовой Telegram ID владельца
Значения из панели имеют приоритет над .env
Запускай только одну копию с этим токеном и сохрани базу на постоянном диске
Если обновляешь старый проект, сначала сделай копию его файлов и базы, для этого проекта выбери отдельный DB_PATH

Для запуска на Mac из папки проекта

```sh
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполни .env перед запуском
python main.py
```

Открой личный чат, отправь /start и нажми «Добавить тему»
Введи запрос, затем открой нужные фильтры в карточке темы
Цена задаётся как максимум в USD или UZS, пересчёта между валютами нет
Город укажи как в выдаче OLX, регистр не важен
Ключевые слова разделяй запятыми, каждое должно встретиться в заголовке или описании
Один дефис снимает фильтр города, цены или слов
Команда /menu открывает меню, /cancel отменяет ввод

## Периодичность и хранение

| Переменная | По умолчанию | Для чего |
| --- | --- | --- |
| CHECK_INTERVAL | 120 | Секунды от окончания проверки до следующей, минимум 15 |
| REQUEST_GAP | 3 | Минимум секунд между началами запросов, нижняя граница 2 |
| MAX_PAGES | 2 | Число страниц на тему за проверку, от 1 до 10, до 40 объявлений на страницу |
| FETCH_PHONE | 1 | Попробовать получить номер, 0 отключает запросы |
| DB_PATH | olx.sqlite3 | Файл SQLite с темами, историей цен и очередью сообщений |

Один процесс по очереди проверяет темы, начиная с тех, чья проверка назначена раньше
Ручная проверка ставит активную тему в ту же очередь
При 429 бот ждёт минимум 120 секунд, при 403 минимум 15 минут, больший Retry-After учитывается
Бот не использует прокси, браузер или обход ограничений
На бесплатном сервере мониторинг работает, пока хостинг поддерживает процесс запущенным

Для новых тем бот отсчитывает новые объявления от момента добавления по полю created_time
Поднятие объявления не меняет эту дату
При возобновлении пропускаются объявления, созданные за время паузы
Цена сравнивается при повторном появлении ID в проверенной выдаче, уведомление приходит при снижении в той же валюте, если новая цена проходит фильтры
При большом количестве тем обход занимает дольше, а объявления за пределами MAX_PAGES могут остаться незамеченными

История хранится по паре «тема и ID», записи без повторного появления удаляются через 30 дней
Одно объявление может прийти по разным темам
Запись о находке и задание на отправку сохраняются вместе, очередь переживает перезапуск
При аварии после отправки в Telegram и до подтверждения в SQLite возможна повторная доставка
Если очередь растёт из-за недоступности Telegram, проверь лог и свободное место на сервере

Фото не загружаются, предпросмотр ссылок отключён, время публикации указано по Ташкенту
Если API занят или номер недоступен, бот отправляет карточку без телефона

## Проверка проекта

```sh
python -m compileall -q .
python -m unittest -v
```

Автотесты используют SQLite и имитацию Telegram и OLX
Для проверки доставки через настоящий Telegram запусти бота с токеном и отправь /start из аккаунта OWNER_ID

## Переход с codexc01/olxparser013

Оставь стартовый файл run.py и Python 3.12 в настройках хостинга, обнови библиотеки из requirements.txt
При запуске через run.py бот принимает прежний BOT_TOKEN и ADMIN_IDS с одним числовым ID, иначе укажи OWNER_ID
Старая версия использует таблицу searches и поисковые ссылки, новая хранит текстовые запросы в таблице topics
Новая версия по умолчанию создаёт отдельный файл olx.sqlite3, старый olx-monitor.db сохрани для отката
Темы из прежнего бота нужно добавить заново
Перед сменой версии проверь выдачу с IP сервера через DIAGNOSE_ONLY=1

Прежнее приложение, его тесты и Docker с PostgreSQL сохранены, инструкции находятся в README-legacy.md
Для прежнего запуска с Python используй requirements-legacy.txt и legacy_run.py
